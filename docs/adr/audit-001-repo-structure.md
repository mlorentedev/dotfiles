# AUDIT-001 — Repo Structure

> Top-level directory + root-file audit. Baseline: [AUDIT-004 architecture map](dotfiles-architecture-map.md). Generated 2026-05-19.

## TL;DR

The repo's **top-level structure is healthier than it feels**. User reported "se está yendo de las manos" — the felt bloat is in `scripts/` (43 files, REFACTOR-001 territory), not in directory organisation. 13 top-level dirs are all referenced by setup / CI / docs — **zero true orphans**. Only one root file is clearly dormant: `run_pssa.ps1` (redundant with CI's inline PSScriptAnalyzer step).

Consolidation candidates exist (e.g. `shells/{zsh,powershell}/` umbrella) but **cost > benefit** under analysis: setup scripts deploy each shell config to a different `$HOME` target, so consolidating the source dirs adds indirection without simplification downstream.

**Output of this audit: 1 deletion PR + 1 cosmetic rename PR (optional) + a clean "no further restructuring needed" stance for the rest.**

## Consolidation analysis

### Candidate: `shells/{bash,zsh,powershell}/` umbrella

**Hypothesis:** merging `.zsh/`, `powershell/`, and RC files (`.zshrc`, `.bashrc`, `.profile`) under a new `shells/` dir would group all shell init by concept.

**Cost analysis:**
- `setup-linux.sh` symlinks `.zshrc` from `~/.dotfiles/.zshrc` to `~/.zshrc`. Moving the source to `shells/zsh/.zshrc` would require updating every symlink target — a ~10-line `setup-linux.sh` change.
- Same for `powershell/profile.ps1` → `shells/powershell/profile.ps1`.
- Deploy targets in `$HOME` stay unchanged regardless of source organisation.
- Net effect: source-side cosmetic improvement, deploy-side identical.

**Benefit analysis:**
- Mental model: "shell stuff lives under `shells/`" is cleaner than scattered.
- But the dirs are already discoverable: `.zsh/` reads as zsh-specific at a glance.

**Verdict:** **DEFER.** Cost ~30-50 LOC of setup changes; benefit is cosmetic. Reconsider when adding a third shell or significantly refactoring setup.

### Candidate: `terminals/` (plural) for future emulators

`terminal/` is currently a single emulator (ghostty). If alacritty / kitty / wezterm get added, the singular name becomes awkward.

**Verdict:** **OPTIONAL RENAME.** Low-cost (1 dir rename + 1 setup-linux.sh path update). Defer until a second emulator lands; premature otherwise.

### Candidate: `config/` umbrella for root SSOTs

Move `versions.conf`, `env-contract.json`, `mcp-servers.json` into `config/`.

**Cost analysis:**
- Every script that reads these would need its path updated. `versions.conf` alone is read by both setup scripts, both shell RC files, CI workflows, and bats tests. ~15+ files to touch.
- The 3 files are *already at the root* — they're at the natural "top of stack" location for SSOTs. Pushing them down a directory level adds indirection without organising any sibling content.

**Verdict:** **REJECT.** High blast radius, near-zero structural benefit. Root-level SSOTs are conventional in dotfiles repos.

### Candidate: collapse `ssh/` into `sensitive/`

`ssh/` holds `config` + public key. Public key isn't a secret; private keys live in `sensitive/` as `.secret.age` blobs.

**Verdict:** **REJECT.** Mixing public + encrypted-private blurs the security boundary. Keep separate.

## Observations (not action items)

- **The `ai/` subdirectory is the largest cohesive area** (42 files) and is structured per-agent + `skills/`. Good signal for future agent additions: each agent gets its own subdir, no flattening.
- **`scripts/` is the bloat zone** (43 files). AUDIT-001 confirms it's a single-directory problem, not a top-level layout problem. REFACTOR-001 owns the deeper audit.
- **Tracked dotfiles at root** (`.zshrc`, `.bashrc`, `.profile`, `.gitignore`, `.pre-commit-config.yaml`, `.PSScriptAnalyzerSettings.psd1`) co-exist with regular files. Some dotfile-repo conventions move them under `dotfiles/` or `home/`; this repo chose root-level. **Consistent with most dotfiles repos in the wild** — no change needed.
- **`specs/` will keep growing** post SDD-003 enforcement. Watch for clutter; current `active + archive` split is sufficient (and SDD-001 is the lifecycle gate).
