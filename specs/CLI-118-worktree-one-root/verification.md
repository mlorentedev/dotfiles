## Decisions made during implementation

Brief log of non-obvious trade-offs or course corrections taken during the work. Routine choices belong in commit messages, not here.

- `done <slug>` resolution moved from PR 4 into PR 1: once `add` writes under the root, a sibling-only `done <slug>` would have broken in between.
- `list --all` needed no change: it finds worktrees through `git worktree list`, not by directory layout.
- `add` refuses when WORKTREE_ROOT resolves empty and no `--path` is given (`TestAddRefusesWithoutARoot`), and `done` says the root was not searched (`TestWorktreeDoneSaysWhenTheRootWasNotSearched`). `env.ResolvePath` returns "" when env-contract.json is neither deployed nor reachable from the cwd; falling back to the sibling there would pick the layout by accident. Measured on the Mac the same day: `DOTFILES_REPO_DIR` names the main checkout, which reads its own env-contract.json first, and until PR 1 lands that file has no WORKTREE_ROOT. The dev build refused (`WORKTREE_ROOT could not be resolved`) where the previous code would have made `dotfiles-wt-<slug>` silently.
- dotf creates the worktree and herdr only opens it (owner, 2026-10-14), so the lease, branch check and isolation gate hold on every path, Windows included.

- `done` identifies a worktree under the root by its branch slug, the one name herdr's layout gives it, not by a second slug recorded in the lease: a herdr-made or adopted worktree would never carry that slug (#2527 review, PR-Agent finding 1).
- The planning tokens are exactly the words of `harness/enforced/no-phase-references.md` (phase, milestone), not the four the first draft named: that file is extracted from the vault's git-workflow pattern, and a validator that bans words the doctrine does not would be a second, unwritten rule. Widening it is a vault edit first.
- `add` with no `--base` used to branch from the caller's HEAD. It now fetches and uses origin's default branch, and refuses when none resolves; a failed fetch (offline) warns and uses the last-fetched refs. git 2.48+ restores origin/HEAD on fetch (`remote.<name>.followRemoteHEAD`), so the master fallback is reached only where that is off or the remote has no HEAD.

- The transcript key is computed from the physical path. Claude Code keys a project on getcwd: on this Mac the one scratchpad session under /tmp is `-private-tmp-…` and no project directory starts with `-tmp-` or `-var-`. done passes git's toplevel, which is physical too; the path as given is kept as a second key.
- The transcript store failing to read is a refusal, not "no session": done refuses (overridable with `--ignore-recent-session`) and sweep skips, naming the error. A missing store is still no session; an entry vanishing mid-walk is a session ending, not an error.
- done checks the session last, under the lock and after the git checks, so a write during those checks counts. sweep checks it after gate f, which also keeps the main checkout out of the report: its key prefixes every legacy sibling's (`dotfiles` vs `dotfiles-wt-x`), found by the #2556 test. No check closes the gap between reading the store and removing the directory; it only narrows it.
- A project directory whose name extends the worktree's key by `-` counts (a session started in `wt/cli`). It also matches a sibling `feat-x-y` for `feat-x`: a false refusal, the safe side, and the message names the transcript.

- UNADOPTED applies to every linked worktree without a lease, not only those under WORKTREE_ROOT as the proposal says: a git-created sibling is just as unknown to sweep, and `adopt` works on any linked worktree. Nothing outside the worktree package read the old ACTIVE "no dotf metadata" state (git grep).

- done deletes a branch only on a verified landing: its tip is an ancestor of the base, or the head of a merged pull request (a squash leaves no ancestor). Any other answer keeps the branch with the reason, `--force` included: `--force` overrides the worktree's dirty and unpushed checks, and after it the branch may be the only copy of the work. A `gh` failure keeps it too, naming the error (`TestDoneKeepsTheBranchWhenThePullRequestLookupFails`; reading the error as landed fails it).
- The branch and tip are read before the worktree is removed, because after removal the worktree's HEAD is gone; the deletion runs after removal, because git refuses to delete a branch a worktree has checked out. The SHA is printed so `git branch <name> <sha>` restores it.
- `main` and `master` are never deleted, nor is a detached HEAD: there is no branch to name.
- `migrate` moves a worktree out of the directory a Claude Code session is keyed on (`getcwd`), so it skips any worktree with a transcript in the last six hours rather than orphan the session; the help text says a session started in the old path does not follow it.

- AC7's `--ignore-recent-session` exists on `done` only. `sweep` and `migrate` act on many worktrees at once, often unattended, so a worktree with a recent session is skipped with the reason printed, never overridden; the operator who knows the session is dead runs `done <it> --ignore-recent-session`, one worktree at a time.

- A herdr failure whose stdout is not herdr's error JSON (a crash, a signal) names the runner's error rather than ending in a bare colon (`TestAFailureWithoutHerdrsErrorJSONStillSaysWhy`, from the #2565 review).
- herdr's agent names are per server, so the same branch slug in two repositories collides. The refusal fails closed and names the likely cause; it no longer suggests renaming the live agent, which may be the other repository's. Putting the repository in the derived name is left to the owner: it changes the naming this spec records, and the 32-character cap would then cut the slug.

- PR 7a (manifest reader): `paths` on a TOML source is gated at version 6 rather than allowed at 5. 0.71.0 reads version 5 and refuses `paths` on TOML per entry, which would blame the herdr entry; at 6 the same binary says the schema is newer and to update dotf, which is the fix. `dotf update` does not read the manifest, so a stale box heals itself.
- The rendering codec is chosen by the source's extension, as ParseManifest's checks are; a replace installs the source's bytes whatever the destination is called (`TestDeploy_PathsRenderBySourceFormatNotDestination`). go-toml keeps an int64 and a datetime across the re-encode (`TestExpandPaths_TOMLKeepsValuesItDoesNotRender`).
- Mutations on PR 7a, each run against `go test ./internal/deploy/`: drop the version gate, gate at 5, render every source as JSON, encode TOML as JSON, choose the codec by destination. All five killed.
- The live `add --agent` check must not start a second herdr server: herdr 0.9.3 isolates only by `HOME` (lesson 446, measured 2026-10-16 when a "scratch" server resumed the operator's agents).

- #2569 (BUG-148): done, sweep and migrate consult every harness store that resumes a session from its directory, in one table (`SessionStores`, `RecentHarnessSession`). pi keys a directory by the path (`--<path, / as ->--`), Copilot keys by session id and records `cwd:` in `workspace.yaml`, so its row reads every session; lesson 447. Tests: `TestRecentHarnessSession` (pi in the worktree, in a subdirectory, stale, another worktree; Copilot in a subdirectory, stale, a sibling sharing the prefix; Claude Code; none), `TestRecentHarnessSessionFailsClosedOnAnUnreadableStore`, `TestPiSessionKeysOnlyForAPOSIXPath`, `TestSessionSkipReasonNamesTheHarness`.
- Mutations on #2569, each against the session, sweep and migrate tests: drop the Copilot row, drop the pi row, drop pi's subdirectory match, swallow a `workspace.yaml` parse error, read any store error as absent, match Copilot's cwd by bare prefix, ignore the window, date a Copilot session by `workspace.yaml` only, key a Windows path for pi, drop the harness name from the skip reason. All ten killed.
- Live read on the Mac (2026-10-16, a throwaway test, not committed): each of the nine dotfiles worktrees resolved against the real stores without a read error, including the one Copilot session.
- A store that exists and cannot be read, a Copilot `workspace.yaml` that does not parse included, refuses done and skips sweep and migrate, naming the harness and the file: one corrupt session of another harness blocks removals until fixed or overridden. A store that is absent, and a harness whose store is not keyed by directory (agy), consult nothing.
- AC9: AGENTS.md §9 and the two vault skills (knowledge `f9f68924`) name `dotf worktree add` and `<WORKTREE_ROOT>/<repo>/<branch-slug>`. The handoff skill already refused to remove the launch worktree (step 3.2); it now removes others with `dotf worktree done <branch>`. Every claim the skills make was checked against 0.71.0: `add` refuses `-b nope` with "is not <type>/<kebab-slug>", forks from origin's default branch, and `done` deletes a landed branch.
- The skills pass `done` the branch, not the slug: a bare name resolves to `<root>/<repo>/<name>` or `.../feat-<name>` only (done's help), so `done <slug>` misses a worktree made with `-b fix/<slug>`, whose directory is `fix-<slug>`.
- `compile-harness.sh --refresh` reads `$VAULT_PATH`'s working tree, which defaults to the shared vault checkout. That checkout held another session's staged work and lacked the commit just pushed, so the first refresh left both skills unchanged. The records were refreshed from a detached worktree of `origin/master` (`VAULT_PATH=<wt> compile-harness.sh --refresh`); reading the working tree is the root cause of #836 (HARNESS-060), measured there.
- AC10: ADR-032's 2026-10-13 amendment carries the owner's clarification as a dated paragraph after point 5: `dotf agent run` is dispatch, `add --agent` is cockpit use that reports submission only.
