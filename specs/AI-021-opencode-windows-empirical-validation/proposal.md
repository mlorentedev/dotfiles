PR #78 (AI-014) cabled the OpenCode Windows install (winget) + config deploy. No empirical shake-down has happened post-merge. Linux equivalent (AI-011-validation) was completed 2026-05-17. Cross-OS confidence story for the multi-agent runtime requires this Windows pass before further OpenCode changes ship. Bonus sub-scope: investigate Gemini-via-OpenCode as a possible fallback for the gemini-cli sunset (2026-06-18), pending Google AI Plus auth-flow constraints.

## What

Empirical validation pass on Windows: re-run setup, launch OpenCode TUI, walk through the 12-step checklist (mirrors AI-011-validation Linux flow). Plus a 7-step sub-investigation on whether `ai/opencode/opencode.jsonc` can route Gemini Pro/Ultra through OpenCode using AI Plus credentials. Findings documented as deltas in `40-runbooks/guide-opencode-go-setup.md` (or a new `guide-opencode-providers.md`). No code changes in this ticket — pure empirical.

## Out of scope

- **Modifying `setup-windows.ps1`** — code fixes discovered open atomic follow-up PRs (AI-022+).
- **Modifying `ai/opencode/opencode.jsonc`** — if Gemini-via-OpenCode is viable, the config change ships in a separate atomic PR.
- **Performance benchmarking** (token/sec, time-to-first-token) — qualitative impressions only.
- **Ghostty integration on Windows** — no port exists yet; out of scope.

## Risks / open questions

- **R1**: AI Plus auth flow. Google AI Plus tier does NOT support Plan Linking with AI Studio API keys (per official moderator 2026-05-21). An API key from an AI Plus user falls back to PAYG, NOT subscription billing. OpenCode using such a key would be PAYG, not Plus quota.
- **R2**: Does OpenCode support an OAuth provider for Google (mimicking `gemini-cli`'s OAuth)? If yes → AI Plus subscription billing preserved. If no → API-key only → PAYG. Phase 1 of the investigation reads OpenCode provider docs (`opencode.ai/docs/providers/`).
- **R3**: gemini-cli sunset (2026-06-18). If Gemini-via-OpenCode works AND user is on free/Google One, this becomes the user's primary Gemini path — high value. If user is on AI Plus and OAuth flow is preserved by OpenCode, even higher value.
- **R4**: PR #78 is a few weeks old; PATH wiring on Windows may have drifted. Pre-flight: re-run `setup-windows.ps1` first.

## Acceptance criteria

### Phase A — OpenCode Windows shake-down (12 steps)

- [ ] `winget install SST.opencode` succeeds (or already installed).
- [ ] `opencode --version` reports 1.15.x.
- [ ] `~/.config/opencode/opencode.jsonc` SHA256 matches repo source.
- [ ] `~/.config/opencode/commands/` contains all 12 `.md` files.
- [ ] `opencode` TUI launches; `/connect` resolves Go subscription (manual API key paste).
- [ ] `/models` lists the Go catalog (12 cheap Chinese LLMs; no Sonnet/GPT/Opus/Gemini).
- [ ] `qq` + `qf` PowerShell aliases work end-to-end.
- [ ] Hive MCP tools available inside an OpenCode session.
- [ ] Windows-specific deltas (if any) documented in `guide-opencode-go-setup.md`.

### Phase B — Gemini-via-OpenCode sub-investigation (7 steps)

- [ ] OpenCode provider doc reviewed; identify `google` / `google-ai-studio` / `gemini` provider availability.
- [ ] Auth method confirmed (API key vs OAuth).
- [ ] AI Plus subscription-exemption from June 18 sunset verified via `goo.gle/gemini-cli-migration`.
- [ ] If provider exists: candidate `opencode.jsonc` block drafted (NOT committed).
- [ ] `/models` picker confirms Gemini models appear when block is enabled (temp eval only).
- [ ] Cost/latency vs Antigravity-direct vs OpenRouter compared qualitatively.
- [ ] Findings written up in runbook section.

### Outcome

- [ ] Clear go/no-go on Gemini-via-OpenCode for AI Plus users.
- [ ] Vault `11-tasks.md` AI-021 entry ticked with the link to the runbook.
