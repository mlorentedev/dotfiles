### Verdict

FAIL — one **Blocker (REAL)**: AC1/AC2's stated coverage ("every routing pin (site)") is falsified by three undeclared committed pin sites (four values `VerdictUnknown` under the guard's own `Check`), with three further REAL Majors: undeclared in-file routing pins (dead-id mutation passes), a CI trigger that skips the guard when the registry or a pin site changes, and a `Normalize` that accepts a dropped declared prefix. Under the reality axis a REAL Major alone forces FAIL; the first is a spec violation, not a hypothetical.

### Recommended next steps

Non-contract set (editable without invalidating this verdict; for the implementer to disposition in `verification.md` — applied, ticketed, or declined with a reason):

1. **Declare the missing sites**: `ai/agy/settings.json`, `ai/claude/settings.json`, `ai/copilot/settings.json`, each with its normalization rule and a `why`. Decide the rule for claude's variant spelling (`opus[1m]`, and `advisorModel`) and agy's display-name form (`"Gemini 3.7 Flash (High)"` vs `gemini-3.7-flash`) *before* adding — a wrong rule manufactures false drift, which is the failure this registry's own `$comment` warns about.
2. **Declare the in-file pins**: `small_model` and the scoped agent `model` entries in `ai/opencode/opencode.jsonc` (nested, so the extractor needs more than a top-level `json-path`) and `fallback_models` in `.pr_agent.toml`. This is CLI-visible, not just data.
3. **Make `Normalize` require the declared prefix** when one is declared (error on a value that does not carry it), or add a test recording that tolerance as deliberate. The mutation in Finding 4 is the regression test to add either way.
4. **Add each newly declared pin to the CI trigger** (`cli.yml`'s `go` filter) — and add a test asserting the filter covers every file `harness/model-pins.json` names, so the next pin site cannot be added without the guard running on it.
5. **Cover the dead-id injection per pin**: one named test that fails when a dead id is written into each declared pin, since `TestEveryRepoRoutingPinResolvesInTheMap` passes on exactly that injection today.
6. Consider making a rotted locator in `checkModelPins` a `Fail`, or suppressing the `Pass("… all resolve …")` line when a pin errored, with a named test; and correct `pi-default-model.why`, which still describes `qwen3.6` while the file pins `deepseek-v4-flash`.

Contract set (`proposal.md` / `tasks.md` / `features.json`) — do **not** edit under this verdict: AC1's "schema-validated" and AC1/AC2's "every routing pin" overstate what shipped. If the human prefers to keep the guard deliberately scoped to declared pins, that is a legitimate decision — but it must be re-worded in `proposal.md`, which invalidates this review and requires a re-review. The spec should not archive until one of those two paths is taken.
