### Recommended next steps
- **Code + tests (`cli/internal/harness/pushguard_lex.go`, `cli/internal/harness/pushguard_test.go`)**:
  - Only run `stripHeredocs` when `shell == ShellPOSIX`; skip `<<` inside `$(( ... ))` / `(( ... ))` arithmetic (or require `<<` to be preceded by command/redirect context rather than an arithmetic expression), and for `shellFeeder` / multiline heredocs check adjacent continuation/pipeline lines (`bash \\\n<<EOF`, `cat <<EOF |\n...\nEOF\nbash`) and quote-stripped shell names (or fail closed when a `<<` body contains `git` and `push` and the feeder is ambiguous).
  - In `backslash`, elide `\<newline>` outside single/`$'...'` quotes as POSIX line continuation instead of emitting `\n` into the token.
  - In `redirectRest` / `stripRedirects`, consume a separate target word when `>&`, `<&`, or `<>` has no attached target (`rest == ""` or `<>` alone), rather than leaving `/dev/null` or `1` as `cmd[0]`.
  - Mark `cd`/`pushd` inside a pipeline (`|`) or background job (`&`) as subshell-scoped (or `dirKnown = false`) so `cd /feat | git push ...` does not leak `dir` into subsequent commands.
- **Code + tests (`cli/internal/harness/pushguard.go`, `cli/internal/harness/pushguard_test.go`)**:
  - In `readOption`, set `o.moves = true` for `name == "sudo"` when `-D` (`strings.HasPrefix(t, "-D")`) is passed.
  - Handle options after `time` (such as `time -p`) in `simple` instead of leaving `-p` as the command name.
  - Add named regression cases for every reproduced bypass above in `cli/internal/harness/pushguard_test.go`.
- **Spec (`verification.md`, `features.json`) + re-review**: Update `verification.md` and `features.json` evidence to the final commit SHA after fixing, and run a fresh adversarial review pass.
