### Round 1's two findings, independently re-verified (floor, not ceiling)

**Blocker (Windows YAML duplication) — CLOSED, verified.** At `508ca10`, `Convert-SkillRecord` had no strip rule (confirmed by reading that commit's `setup-windows.ps1` directly: no `-cmatch`/strip logic present). At `8e0d891`, it does (`setup-windows.ps1:1822`, `if ($fm -eq 1 -and $line -cmatch '^generated(_from|_sha)?:') { continue }`). `pwsh` is not installed on this machine — confirmed (`which pwsh`, `command -v pwsh`, package search all empty) — so I could not execute the PowerShell function live, same constraint the implementer disclosed. To get real signal anyway: I extracted the bash `awk` block from `render_skill` and ran it verbatim against a fixture record that already carries its own `generated_*` fields (the exact shape a HARNESS-069-refreshed record has), then separately hand-ported `Convert-SkillRecord`'s loop to Python, preserving its conditional structure exactly (frontmatter-count gating, the `command`-kind `name:` drop, the new strip check). I then disabled the strip check in the Python port (simulating round 1's original bug) and reran: 2 stacked sets, 6 `generated*` lines instead of 3 — confirming the new bats assertions (`grep -c ... -eq 1`) would have gone red on the original bug. Confidence: high for logic correctness (the port is a direct transliteration verified line-by-line against the bash reference, not an approximation); the one residual gap is that no PowerShell interpreter — mine or the implementer's — has actually executed this exact code. See "CI execution" below for why that gap is closed elsewhere.

`-cmatch` case-sensitivity claim, verified against source, not the comment: Microsoft's PowerShell docs (`about_Comparison_Operators`, `lang-spec/chapter-07`) state plainly that "the default `-<operator>` version is equivalent to the case-insensitive variant" and the `c`-prefixed forms are case-sensitive, with a worked example showing `"Hello" -cmatch '^h.*o$'` → `False` while `-match` → `True`. The code comment's claim is correct.

**Major (`generated_from`/`generated_sha` referent mismatch) — CLOSED via spec correction, verified consistent with actual code on both hops.** Read both provenance write sites directly, not just the doc comments describing them:
- Record-level (`--refresh`, `inject_record_provenance`, called at `scripts/compile-harness.sh:434` for skills / `:464` for agents): `srcpath` = vault-relative path (`"$sk_vsub/$name/SKILL.md"`), `sha` = `sha_of` **the vault source file** (`$sk_dir/SKILL.md`, the vault-side path). Both fields describe the same file (the vault source) — internally consistent, no referent split at this hop.
- Deploy-level (`--deploy`, `render_skill`/`Convert-SkillRecord`, called with `record="$sk_dir/SKILL.md"` where `sk_dir` is now the **committed record** directory, `srcpath` still the vault-relative path): `sha="$(sha_of "$record")"` hashes the **record**, `generated_from` still names the **vault**. Two different files in one field pair, exactly as the corrected `proposal.md` AC2 text and the new doc comments in both `render_skill` and `Convert-SkillRecord` now state.
- `render_agent` (unchanged, allowlist `name`/`description` only at `fm==1`) drops any pre-existing `generated_*` from a record naturally — read directly, confirmed true, no fix needed or made.
This was a legitimate resolution path: round 1 itself offered "fix the code" or "fix the spec" as equally valid, and changing the code (making `generated_from` record-relative at deploy) would have made the field *less* useful for a human's actual use case ("where do I edit this" — always the vault, stable across every hop). The reworded AC2 in `proposal.md` matches what the code has always done at the deploy hop and matches what round 1 confirmed was pre-existing/unrelated to this diff.

### New findings (beyond round 1's floor)

So this is real, reproduced, silent, and low-impact: a committed-record hygiene defect, not a functional break reaching `$HOME`.

The assertions themselves are correct (pure `grep -c`/`grep -q`, unaffected); only the prose reverted to the pre-fix mental model.

Round 1's own Minor (opencode/copilot AC2 assertions check only `generated_from` count, not all three fields, asymmetric with the claude block) is unresolved — confirmed via `git diff 508ca10..HEAD -- tests/compile-harness.bats` returning empty.
